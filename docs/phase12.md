# Overrides, reconciliation and replay

Decoded activities and their source observations are immutable inputs to overlay replay. User annotations, classification corrections and exact movement-amount corrections are stored as append-only overlay revisions keyed by stable activity and movement IDs. Re-decoding and re-import do not rewrite overlays. If a new decoder no longer emits a corrected movement ID, replay preserves the edit and reports the unresolved ID; it does not attach the value to a different movement.

Classification rules have IDs, priority, match criteria, enabled state and append-only versions. Replay evaluates current enabled rules against the original decoded activity, using descending priority and ID as the tie breaker. A user classification takes precedence over a matching rule; the original classification is the fallback. Each replay result includes the untouched original, effective activity, label and note, applied rule ID/version or user origin, overlay revision, and unresolved corrections. Replaying the same inputs and versions is deterministic. Edits may clear prior values by writing a new complete overlay snapshot.

Reconciliation only suggests opposite signed, exactly matching asset quantities in different accounts within a caller-provided time window. Matching is conservative evidence, not a proof of shared economic identity. Suggestions include a deterministic score and flag ambiguity whenever one record has multiple candidates or multiple movement pairs match. No suggestion merges or deletes activities or source observations. Explicit reviewer accept/reject decisions are durable and versioned, and consumers must apply appropriate linkage policies when building projections.

Reviewers can also explicitly identify two activities as duplicate source representations and choose the canonical record. Projection replay suppresses only unambiguous equal movements with the same account, asset, signed quantity and role in the noncanonical record. Other legs, including fees, remain; transfer links retain both sides. The result identifies each suppressed and canonical event and flags missing, ambiguous or conflicting records. Original activities and provenance remain intact.

The application suggestion queue excludes accepted and rejected pairs using their latest persisted decisions. Reviewing a pair leaves the original ledger intact and updates ambiguity among the remaining suggestions.

Effective-ledger replay resolves accepted decisions into explicit outgoing and incoming movement relationships after duplicate suppression. Missing, inactive, ambiguous, corrected or multiply claimed movements produce explicit projection conflicts instead of an arbitrary match. These relationships preserve both activities and do not infer ownership or accounting treatment. The settings rule manager lists current rules and supports editing, disabling and re-enabling them while retaining their IDs, priorities and match filters.
