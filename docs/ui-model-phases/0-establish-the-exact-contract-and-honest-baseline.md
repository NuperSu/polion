# Phase 0 — Establish the exact contract and honest baseline

Read the [roadmap index](../ui-model-functional-roadmap.md) and its delivery rules. This phase has no earlier phase prerequisite. The deliverables are the [parity inventory](../ui-model-parity.md) and [capture evidence](phase-0-captures.md), including the review required by the exit below.

Capture the model and the production app at 360×800, 390×844 and 1440×900, including scrolled sections, every detail tab, add-method selection and transaction forms. Inventory every visible field, chart, icon and action. Record each as implemented, partially bound, unsupported or undefined, with its source and destination.

Specify the ambiguous items: the Portfolio change period; the distinction between value change and return; price-change windows; average buy/sell price; total gains; Decisions; exchange usage; trade counts; fee conversions; benchmarks; and Asset Worth. Define chart ranges and empty/loading/offline/error states. Define which UI changes are necessary for accurate financial language without changing the overall composition.

**Exit:** a screen-by-screen parity checklist, matched reference captures, metric definitions and an action-to-destination map. Existing test/build evidence is recorded separately from unfinished acceptance. No screen is declared complete from theme similarity.

## Completion record

**Complete as a baseline**, 2 November 2026. The [parity inventory](../ui-model-parity.md) records the source and action map, proposed metric definitions and surface states. [Capture evidence](phase-0-captures.md) records the tested source revision, paired review, differences and limits. Review establishes the baseline and does not pass visual fidelity, financial correctness, interaction coverage or platform release gates. Proposed definitions require user agreement before they are treated as approved specifications.

## Run and record

Use [the parity inventory](../ui-model-parity.md) as the working checklist and [capture evidence](phase-0-captures.md) as the capture and review record; include the exact revision for each capture set. Capture both applications at each specified size and identify screen, tab, form, scroll position and state in each image's name or index. Compare each pair for section order, structure, controls and visible content; record discrepancies and reviewer/date. Capture model examples as examples, not financial evidence. Cover empty, loading, offline and error states in the contract even where the model has no such visual reference.

Document proposed defaults for ambiguous metrics as deliverables; do not represent them as agreed product decisions. Complete the source/action inventory and proposed metric contracts without waiting for later-phase services: an explicitly unsupported feature with its destination and implementation phase is a valid baseline finding. Keep build/test, desktop launch and Android launch evidence separate. The phase is complete only after matched captures are reviewed and the checklist, action map and definitions meet the exit above; the review does not imply that any production screen is functionally complete.
