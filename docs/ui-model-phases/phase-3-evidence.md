# Phase 3 — Transaction system

## Ledger and accounting contract

`TransactionDrafts` constructs exact movements and explicit accounting treatments. `PortfolioApplication.saveTransaction` validates current account ownership and historical asset precision, then commits all legs, treatments, notes and execution evidence in one SQLite transaction. Draft evidence uses existing portable application settings; ledger and source identities retain their existing storage.

- Buy acquires the gross executed base quantity and disposes the exact quote consideration. Sell disposes base and acquires quote. The product of quantity and unit price must fit the quote asset's atomic precision; unsupported fractional consideration is rejected rather than rounded.
- Fees are separate negative movements with zero disposal proceeds: their consumed basis is expensed, rather than capitalized or deducted from gross execution consideration. Fees in the base or quote are supported; another registered asset requires an explicit evidenced quote conversion price, retained with the execution evidence. Missing fee acquisition basis remains unknown. This is an explicit local accounting policy, not a jurisdictional tax specification.
- Internal transfers require different active accounts owned by the same owner. The existing FIFO transfer action preserves lot age and basis, including unknown basis. Cross-owner internal transfers cannot submit. External incoming transfers create unknown opening basis; external outgoing transfers have unknown proceeds. They are not invented sales or cost evidence.
- Deposit and Reward accept optional explicitly entered acquisition evidence. Without it basis remains unknown. Withdrawal has unknown proceeds. Standalone Fee is an expense disposal. All submitted quantities are positive; direction is determined by the selected type. Archived/group accounts, mismatched pairs, negative/zero amounts, fractional atomic units and unsupported fee combinations cannot submit.
- Saving an existing identity without edit mode fails. Manual edits retain the activity ID and stable movement IDs for each semantic role; ledger revisions and note overlays preserve evidence. Reversal appends a REVERSED revision so it stops affecting active balances without deleting history. Imported records use the existing correction overlays and provenance tools.

## Shared presentation

The shared full-screen form uses the model's asset/type capsules, fields and pinned primary action. It provides source/account selection, local account creation, pair selection, UTC ISO timestamps, executed quantity and price, fee asset/evidence, counterparty and notes. Review shows the exact signed account movements before committing. Draft fields and review state survive recreation. If a commit succeeds before recreation cancels the UI callback, retry recognizes the identical retained draft, effective activity and treatments instead of creating another record. Notes retain their entered whitespace. Unsupported exchange connections and CSV import remain muted and disabled.

Coin Transactions contains modeled cards ordered by timestamp and stable identity, with type/date/status/source, From, To, Amount, Fee, Worth Now and Worth Then. Unknown counterparties remain dashes. Fee-only records retain their own type. Internal transfer amounts show the moved quantity rather than a misleading zero net quantity.

Worth Now values the displayed gross transaction quantity using a fresh saved current quote. Worth Then uses retained execution evidence for the selected base/quote where the movements have not been corrected, the explicit fee conversion evidence for a fee-only asset, or a fresh eligible saved historical observation. Values in their own quote currency use the exact identity conversion. Neither represents investment return or acquisition basis. Pending/reversed records and unresolved corrections have unavailable worth. Saved manual/provider observations can have limited coverage.

Buy/sell averages divide summed explicit consideration by summed executed base quantity: quantity weighted, gross and excluding separate fee movements. Only confirmed trades with valid treatments in the selected quote qualify; partially eligible results disclose their priced count. Transaction count includes all matching statuses. Search, type/status filters and 20-record pagination are scope-aware and restored after recreation. CSV exports include all matching records across pages while retaining the selected asset/portfolio scope. Card details expose evidence/corrections and eligible manual edit/reversal actions. Entries with movement/classification correction overlays remain in the correction tools rather than the trade editor.
