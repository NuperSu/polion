# Milestone D acceptance map

Phases 21–23 provide the shared Android and Linux desktop product workflows. The final local acceptance run passes; the installed Pixel build matches the validated APK. This acceptance covers the product and device requirements below. It does not certify every separate Milestone C chain-verification requirement or a production release audit.

| Requirement | Implementation and inspected evidence |
| --- | --- |
| 21: portfolios, owners, groups, public addresses/wallets/descriptors | Shared `PolionApp`, `Workflows` and `WalletDialog` call the persisted `PortfolioApplication`. Ownership/scope tests, atomic wallet discovery tests, public BIP vectors and the wallet import UI test pass. Supported grammar and gap assumptions are in [Bitcoin wallets](bitcoin-wallets.md). |
| 21: balances, history, asset details, fiat value and sync status | Shared projections drive both hosts. Asset details expose price observations; activity details expose movements and provenance. The shared Bitcoin financial fixture runs on desktop JDBC and native Android SQLite. Busy-dispatcher UI tests verify that sync progress and saved source settings remain visible. |
| 21: source limitations, pending data, corrections, rules and reconciliation | UI separates pending activity and identifies partial/unpriced/stale data. Persisted correction/rule/reconciliation tests and multi-leg correction/reset UI tests pass. Account removal archives and pauses tracking, with restoration available. |
| Responsive phone and desktop UI | Final packaged-app renders inspected at 360×800, 800×900, 1440×1000 and 800×360. Automated interaction tests cover these sizes plus a 320 dp phone with 1.5× text. Compact bottom navigation, scrollable desktop sidebar, wrapping forms and paginated content support changing sizes. |
| 22: lifecycle and background work | Manual Android sync owns a foreground service, notification, bounded wake lock and separate connection. Emulator Home-switch sync completes; WorkManager retry, success and next-job scheduling are observed. Desktop refresh runs while the app is open. |
| 22: secure storage, privacy, files and wipe | Native Android Keystore tamper/round-trip checks pass. The actual desktop Secret Service adapter passes disposable store/lookup/verify/clear. Shared consent, encrypted staging restore/export and wipe tests pass. Hosts provide native file dialogs. The live database is plaintext and this is disclosed. |
| 22: process death, offline, low storage, upgrade and wrong passwords | Emulator force-stop/retry preserves ledger and endpoint; airplane-mode failure preserves the ledger. Native SQLite-full rollback/integrity and wrong-password restore checks pass. An in-place APK update preserves all 37 application tables and reopens successfully. Privacy-lock restart, wrong password rejection and correct unlock pass. |
| 23: historical/current charts and breakdowns | `analytics`, `historySeries` and textual balances use the same effective ledger, holdings and market projections. Tests compare current allocation with snapshot valuations and assert historical balances/category totals; observation IDs and exact quantities remain traceable. |
| 23: filters, currency, prices, export and accounting | Shared activity filters/search, currency preference, manual quotes and CSV use persisted core services. UI persistence/correction/export tests pass. Shared Bitcoin FIFO fixture verifies decreasing block timestamps, disposal/fee basis, resync, reorg and encrypted restore/CSV equality on both SQLite drivers. Reports offers explicit chain-order verification. |
| 23: performance and view state | Cached ledger/holdings replay is invalidated on mutation/reload. History queries remain independent of activity search; pages preserve scroll state. The 10,000-activity seed/projection/render/search workload passes with bounded composed history rows, measured at 3,225 ms on this machine. |

The final integrated run has **84 core JVM, 28 Android host, 10 shared UI and 3 desktop tests**, all passing, with formatting, Android lint, APK assembly and desktop packaging. Native instrumentation has **7 checks, 0 failures**. Details and runtime distinctions are in [validation](validation.md).

## Operating limits

The selected Esplora indexer remains a trusted, consented source; scanning checks consistency but does not independently prove chain completeness. Supported wallet expressions are bounded and explicit. Mixed-source or unverified Bitcoin accounting chronology leaves affected basis/gain unknown; transaction-order verification does not supply missing acquisition costs. The privacy lock protects screen access, while live SQLite remains plaintext. Desktop background refresh requires the app to remain open. Android scheduling remains subject to operating-system restrictions. No jurisdictional tax compliance, full screen-reader audit, hosted CI execution or production security certification is claimed.
