# Asset identity and price observations

Assets use stable IDs and an independent identity tuple: kind, explicit network where applicable, canonical native/contract reference, and NFT token ID. Token identities on different contracts or networks remain distinct even when they share symbols. Custom and fiat assets use explicitly scoped references. Connectors supply canonical references; case-sensitive chain-specific normalization is not guessed in the core. Asset metadata versions carry symbol, display name, decimal scale and effective time.

Provider identifiers are mapped explicitly to assets. Price observations carry exact decimal value, asset pair, provider or manual origin, market-valid time and observation time. History and current lookups are the same time-bounded operation: only observations valid at or before the requested time and known by the requested observation cutoff are eligible. Manual overrides take precedence and can be withdrawn at an effective time without erasing earlier observations; otherwise fresh quotes are preferred by default, then the caller's provider order controls selection, then newest valid time and observation time break ties. Callers can configure provider priority to precede freshness. A stable observation ID resolves any remaining tie. Provider observations outside the explicit selection list are ineligible. Age is measured against the selected quote's market-valid time. Fresh, stale and missing results are distinct; missing never supplies a numeric zero. Amount valuation preserves exact decimals and leaves rounding to callers.

The market repository owns a versioned transactional SQLite schema. Assets, metadata versions and price observations are durable and idempotently inserted; conflicts fail instead of silently changing identity or history. No live market provider is required. Callers own query time, observation cutoff and staleness policy, allowing deterministic historical replay.

The application registers USD, EUR and GBP fiat identities and metadata for display-currency selection. Selecting a currency does not manufacture exchange rates; missing quotes remain unpriced.

The shared price workflow can request a Bitcoin daily observation in USD, EUR or GBP from CoinGecko after separate, explicit price-provider consent. The Demo history request uses the documented day-month-year wire format and covers dates within the previous 365 days. The optional Demo key is held only for the current request/session and sent in a request header; it is not saved in the database or backups. Access denial, unavailable dates, malformed responses and rate limits do not create zero prices or remove saved observations. Host transports restrict HTTPS endpoints, reject redirects, bound payload sizes and pace requests without sleeping on the UI queue. See the [CoinGecko Demo history contract](https://docs.coingecko.com/demo/reference/coins-id-history).

Saved CoinGecko observations participate in the same exact historical valuation and fresh current-unit-price selection as other stored quotes; manual observations retain priority. Revoking network consent retains offline price history. A consent-generation check inside the observation transaction prevents a request from saving after erasure or a consent change. Android restore also invalidates outstanding price requests. Daily observations do not establish acquisition costs or imply a live market feed.
