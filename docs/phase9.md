# Asset identity and price observations

Assets use stable IDs and an independent identity tuple: kind, explicit network where applicable, canonical native/contract reference, and NFT token ID. Token identities on different contracts or networks remain distinct even when they share symbols. Custom and fiat assets use explicitly scoped references. Connectors supply canonical references; case-sensitive chain-specific normalization is not guessed in the core. Asset metadata versions carry symbol, display name, decimal scale and effective time.

Provider identifiers are mapped explicitly to assets. Price observations carry exact decimal value, asset pair, provider or manual origin, market-valid time and observation time. History and current lookups are the same time-bounded operation: only observations valid at or before the requested time and known by the requested observation cutoff are eligible. Manual overrides take precedence; otherwise fresh quotes are preferred by default, then the caller's provider order controls selection, then newest valid time and observation time break ties. Callers can configure provider priority to precede freshness. A stable observation ID resolves any remaining tie. Provider observations outside the explicit selection list are ineligible. Age is measured against the selected quote's market-valid time. Fresh, stale and missing results are distinct; missing never supplies a numeric zero. Amount valuation preserves exact decimals and leaves rounding to callers.

The market repository owns a versioned transactional SQLite schema. Assets, metadata versions and price observations are durable and idempotently inserted; conflicts fail instead of silently changing identity or history. No live market provider is required. Callers own query time, observation cutoff and staleness policy, allowing deterministic historical replay.
