# Polion plan — medium and long term (November 2026)

This plan orders the work that remains. It does not replace the detailed contracts:

- [Architecture roadmap](../kotlin_portfolio_tracker_long_term_plan.md) — phases 0–32, invariants and acceptance gates.
- [UI-model roadmap](ui-model-functional-roadmap.md) — phases 0–8 for the product screens, each with its own exit gate.
- [Milestone D status](milestone-d.md) and the [code review](review/README.md) — open gates and findings.

Each phase below names the documents it delivers against. A phase is complete only when its exit gate passes with recorded evidence: tested revision, automated checks, Android device or emulator run, desktop run and, for screens, user visual approval. Phases start only when Anton authorizes them.

## Where things stand

Working today, on Android and Linux desktop:

- Bitcoin public addresses, descriptors and xpubs: one-step import with live progress, bounded discovery, staged and atomic history acceptance, reorg and interruption handling, and archive/restore. Importing a tracked wallet resumes it, and an owner's standalone copy of a wallet address moves into the wallet.
- A refresh skips history when the provider's counters and the checkpoint are unchanged, and falls back to the full scan otherwise.
- One Auto-sync switch drives prices (Kraken, hourly) and wallet history (every 30 minutes), with a cooldown after each run.
- Portfolio, coin General and the transaction system (UI phases 2–3); accounts, history refresh and recovery (UI phase 4).
- Settings as a menu: Theme at the top, then General, Portfolio, Notifications, Connections, Security, Devices & Data and Support. Features scheduled for later phases show dimmed.
- Encrypted backup and restore, CSV export, privacy lock and data erase.

Not done or not accepted:

- **User visual approval:** UI phases 1–4 are awaiting it. Phases 5–8 have not started.
- **Gate D:** not accepted. Open items are connector execution through the registry (architecture phase 7), reconciliation integration (12), the descriptor audit (15) and Bitcoin financial acceptance against independent fixtures (20).
- **Review findings still open:**
  - large backups cannot be exported, which needs a streaming backup (CORE-2);
  - SQLite busy timeout and WAL (PLAT-7);
  - database reads on the UI thread (PLAT-5);
  - no recovery path for a forgotten lock password (PLAT-6);
  - example data never goes away (CORE-5);
  - quote freshness is inconsistent (CORE-6);
  - zero prices are stored as fresh (CORE-9);
  - most UI P2 items.
- **Known limits:**
  - large wallets can exhaust memory (`BUGS.md`);
  - the live database is plaintext;
  - legacy and nested-SegWit xpubs are not supported;
  - there is no incremental history fetching;
  - Main's market feeds are placeholders;
  - notifications, alerts, order books and CSV import do not exist.
- **Device evidence for the latest changes is partial:** native checks pass on the phone, but the live unchanged-history skip and the stuck-wallet resolution still need a run on real data.

## Medium term — to the first Bitcoin release

Six phases, in order. M1 must finish before M3; M2 can run alongside M1.

### M1 — Stabilize and accept what exists

Goal: the current product is correct, durable and approved before new surfaces are added.

- **Close Phase 4 with device evidence:**
  - import → discovery → history → balance on the phone, including your stuck xpub;
  - the skip-when-unchanged path against a live provider;
  - the Auto-sync cooldown across a restart;
  - Android `UPDATE` scheduling with an initial delay.
- **Data safety:**
  - a streaming backup export and restore with the same limits on both sides (CORE-2);
  - SQLite busy timeout and WAL on both drivers (PLAT-7);
  - move the remaining UI-thread database reads off the main thread (PLAT-5).
- **Correctness:**
  - one freshness window per quote (CORE-6);
  - reject zero provider prices (CORE-9);
  - let example data be removed (CORE-5);
  - remove the old-tool links from coin and Main pages, so no surface depends on advanced mode.
- **Lock recovery (PLAT-6):** an explicit "forgot password: erase or restore from backup" path, without weakening the lock.
- **Visual review:** you review Phases 1–4 and Settings, and the agreed changes land.

Status: approved by Anton on 2026-11-07. The data-safety, correctness and lock-recovery items are done, including the streaming backup (CORE-2); see the review [fix status](review/README.md#fix-status-branch-review-fixes). Carried forward as small hardening items: PLAT-7 WAL, the 5 MiB response cap, the custom-endpoint chain check and mempool saturation.

Exit: review P1 items closed. P2 items fixed or explicitly deferred with reasons. Phases 1–4 approved. Full checks pass, the native harness has zero failures on the phone, and the desktop smoke run passes.

### M2 — Finish Settings

Goal: every dimmed Settings row either works or is removed.

- **Theme:** System, Light or Dark, chosen at the top of Settings. It replaces the View Options section; monochrome icons and invert red/green were dropped.
- **General:** default landing page (Main, Portfolio or Insights), and an optional secondary fiat currency shown under the Portfolio total. Automatic price refresh also fetches the secondary currency. Language was removed until translations exist.
- **Portfolio:**
  - a show/hide portfolio chart toggle;
  - zero cost basis for rewards. Acquisitions recorded as Reward (mining, staking, forks, airdrops) replay as known zero-cost lots in the report currency. The recorded value is kept, so turning it off restores it. Wallet receipts cannot be marked as rewards yet (L5).
- **Devices & Data:** an editable device name, defaulting to the host name (Android device name, desktop hostname), kept in backups. Transfer and Sync stay dimmed until L6.
- **Support:** an in-app Help page covering wallets, syncing, privacy, backups, the lock, and values and gains; Connections FAQ opens it. Contact support was removed.
- **Security:** fingerprint unlock on Android 11+ with BiometricPrompt over the existing lock. Each unlock uses a Keystore key that requires a strong biometric and is invalidated when fingerprints change. Desktop explains that it is unavailable. Lock settings are per device and not in backups.

Status: implemented on 2026-11-07, awaiting Anton's review. Remaining dimmed rows are scheduled: notifications and CSV import history (M5), Transfer and Sync Data (L6).

Exit: no dimmed row without a scheduled phase. Each setting persists through restart, backup and restore, and has a UI test.

### M3 — Market discovery on Main (UI phase 5)

Goal: Main shows real markets without connecting a wallet.

1. **Provider decision (needs Anton):**
   - compare candidates on terms, attribution, free quota, API key, privacy and cost;
   - the default candidate is CoinGecko (markets, trending, coin charts) with a user-supplied Demo key;
   - Kraken stays for owned-asset prices.
2. **Capability layer:**
   - stable asset identities mapped per provider;
   - each feed (top coins, trending, gainers/losers, sparklines) cached independently with its observation time;
   - coordinated with the Auto-sync cooldown.
3. **Screens:**
   - Top Coins with sparklines, Favorites, Trending, and Top Gainers/Losers within a named universe and window (for example "top 250 by market cap, 24h");
   - coin pages for market-only assets.
4. **Separately or together:** price alerts depend on M5, but the feed layer is shared.

Exit: as in UI phase 5. Every section has a real feed, honest ranking labels, coin navigation, and tested empty, offline and rate-limited states.

### M4 — Insights (UI phase 6)

Goal: Insights reproduces the model with defined financial meaning.

- History, then Portfolio Performance (TWR first; MWR/XIRR only with convergence rules), Diversity, Gains Reporting, Asset Location, and Trade Statistics/Fees.
- Agree definitions before building Decisions and the crypto-market benchmark (needs Anton).
- Independent financial fixtures cover contributions, withdrawals, transfers, fees, and missing basis or prices.

Exit: as in UI phase 6.

### M5 — Notifications, alerts, order books and CSV import (UI phase 7)

Goal: the Notifications page and the remaining model controls are real.

- **Alerts:** a persisted rule model, threshold and direction, cooldown and deduplication, and delivery history. Desktop evaluates while open; Android uses notification permission and scheduled checks. The Notifications settings (daily portfolio update, significant price changes, highs/lows) are built on this.
- **Order book:** one named venue and pair with snapshot plus updates, and gap recovery and stale states.
- **CSV import:** templates, mapping, preview, row validation, duplicate detection, provenance, an import receipt and reversal. The "CSV Import History" row opens these receipts.

Exit: as in UI phase 7.

### M6 — Release acceptance (UI phase 8 and Gate D)

Goal: a packaged, documented first release.

- Full journeys on packaged Android and desktop. Viewports, enlarged text, accessibility labels and keyboard focus.
- **Close Gate D:**
  - connector execution through the registry (7);
  - reconciliation integration (12);
  - descriptor audit (15);
  - Bitcoin financial acceptance against independent fixtures (20).
- Upgrade and restore preserve identities, quantities, treatments, corrections and settings.
- Hosted CI runs and is reported separately from local evidence.
- Published limits: supported wallet types, providers, accounting policy, notification timing and plaintext storage.

Exit: as in UI phase 8. Visual, interaction, financial and platform gates all pass, and remaining scope is stated.

## Long term — after the first release

Ordered by user value and risk. Each phase reuses the core contracts (raw ingestion, connector capabilities, ledger, accounting) and must not special-case one chain in the core. Architecture-roadmap phase numbers are given in brackets.

### L1 — Bitcoin depth

- **Incremental history:** newest pages only, with overlap windows, mempool reconciliation and cursor invalidation. Enabled only after the full-replay equivalence gate in [incremental history](incremental-bitcoin-history.md) passes.
- **Wallet coverage:** legacy (BIP44) and nested-SegWit (BIP49) xpubs, with script-type detection on import, and Taproot descriptors.
- **Large wallets:** streaming snapshots and paged projections so 100k-transaction wallets open within bounded memory (`BUGS.md`).
- **Privacy and storage:**
  - an encrypted live database (SQLCipher or a platform keystore-backed key);
  - optional Tor or self-hosted Esplora/Electrum guidance.

Exit: equivalence tests pass, the memory budget is measured on large fixtures, and encryption at rest survives upgrade and restore.

### L2 — EVM chain family [24, 25]

- An EVM adapter: addresses, native balances, transaction history, and token transfers with stable token identities. NFTs are listed without valuation claims.
- Provider choice and consent mirror Bitcoin: user-chosen endpoint, explicit queries and no hidden aggregation.
- Market discovery (M3) already covers EVM assets, so connecting a wallet attaches holdings to existing coin pages.

Exit: independent fixtures for transfers, fees (gas), failed transactions and token decimals. The "Ethereum Wallet" connection works like Bitcoin's.

### L3 — Exchanges, importers and DeFi [26, 27, 28]

- Exchange connectors via read-only API keys stored in the platform keystore, with a per-exchange capability declaration.
- Generic importers beyond M5's CSV, such as exchange export formats, with reconciliation against on-chain transfers.
- A DeFi decoder framework for common protocols, with unknown interactions kept explicit rather than guessed.

Exit: transfers between exchange and wallet reconcile without double counting. Keys never leave the device keystore.

### L4 — Other chain families [29]

Additional families (for example Solana or Cosmos-style chains), each with its own authorization, fixtures and gate. No family is added without a requesting use case.

### L5 — Advanced accounting [30]

- Policies beyond FIFO (LIFO, HIFO, average cost) as replayable, per-portfolio choices.
- Staking and lending positions, income classification, and fork/airdrop policies (extending M2's zero-basis option).
- Jurisdiction-neutral reporting exports. No tax-compliance claims without separate review.

### L6 — Local multi-device sync [31]

- End-to-end encrypted sync between the user's own devices (desktop ↔ phone), with no required cloud account.
- This makes the Devices & Data rows real: device name, Transfer Data and Sync Data.
- Conflict handling builds on the append-only ledger and revisions.

Exit: two devices converge after offline edits, a lost device can be revoked, and backups remain the recovery path.

### L7 — Hardening and distribution [32]

- Reproducible builds; signed Android releases (F-Droid and/or Play) and desktop packages (Flatpak/AppImage).
- A security review of storage, backup crypto (CORE-13 KDF parameters), the lock and provider requests.
- Performance budgets in CI, and a crash-free upgrade path across releases.

## Working rules carried forward

- Exact decimals and provenance everywhere. Unknown is not zero, and missing data is shown where it applies.
- No private keys, seeds or signing. No required cloud accounts.
- A failed or partial fetch never replaces accepted data.
- Focused commits after relevant checks; no pushes without instruction.
- Device checks use the phone's current Android user and keep app data.
- Visual approval stays with Anton; tests that only find text do not prove design fidelity.
