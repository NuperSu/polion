# Financial contract and performance harness

Shared test fixtures include deterministic clocks, fake provider pages, and deliberate checksum corruption. The chain/exchange fixture file uses stable synthetic values. The JVM integration test exercises provider scheduling, raw provenance, normalized ledger persistence, user overlay replay, price selection, holdings and FIFO gains for independent chain and exchange families, then reopens the database. Corrupted records do not commit or advance the checkpoint. Additional common accounting, holdings, connector, reconciliation and backup tests run under both configured host test targets where platform-independent.

The repeatable JVM benchmark test constructs 10,000 synthetic confirmed activities, times the initial SQLite projection, two unchanged incremental recomputations and a complete replay, and checks all results against the expected total. The test logs elapsed time rather than enforcing a machine-dependent threshold. On the development Linux laptop with JDK 21, an initial run completed this sequence in 1,332 ms. Performance depends on storage, runtime and load; this is not a battery or Android-device benchmark.
